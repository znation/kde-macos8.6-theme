### Fidelity diagnostics: page through horizontal mismatch intervals (planned 2026-11-04 by the plan role)

**Goal and grounding.** Inspect later mismatch segments without printing earlier intervals. `tools/fidelity.py::_filter_run_report` currently filters interval lengths and takes a capped prefix; `main` computes count and longest summaries before that selection. Searches for `--difference-run-offset`, `difference_run_offset` and finished mismatch-paging headings in tools, tests, PLANS.md and PLANS-DONE.md found no horizontal interval paging capability or plan. The completed horizontal-cap entry explicitly excludes pagination. This work is independent of the queued vertical reference-sampler plan.

**Approach and files.** Add optional `--difference-run-offset K`, default None, to `tools/fidelity_cli_parser.py::build_parser`, with a nonnegative ASCII decimal validator in `tools/fidelity_arguments.py` following `worst_pixel_offset` and naming the new flag in errors. In `tools/fidelity.py::main`, require `--max-difference-runs` for an explicit offset, including zero, before reading images; retain the cap's requirement for `--difference-runs`. Extend `_filter_run_report` with a default-zero offset parameter, passing it for horizontal reports while vertical callers retain zero. Apply both inclusive length filters, skip K eligible intervals globally in row-major order, then emit at most the cap. Keep omitted count equal to eligible count minus emitted count, including skipped and trailing intervals. Pass explicit offsets through `tools/fidelity_reports.py::report_data` as optional top-level integer `difference_run_offset`; `tools/fidelity_rendering.py::render_text` prints `difference run offset: K` immediately before the horizontal list. Add `tests/test_fidelity_difference_runs_offset.py` using `FidelityCliTestCase` and generated PNGs following `TestDifferenceRunsLimit`; update README.md beside the horizontal cap and the corresponding docs/invariants.md row. These eight small file changes fit one run; segmentation retains its full interval list, and paging bounds output only.

**Acceptance criteria.**

- Against a black 9x2 reference, a candidate with red-channel delta 20 at x={0,2,3,5,6,7} on row zero and x={0,1,2,3,8} on row one has five horizontal intervals. Cap 2 with offset 2 emits exactly `(5,0,3)` and `(0,1,4)` as `{x,y,length}` records, reports 3 omitted, and includes `difference_run_offset=2`. Offset zero emits the capped prefix with explicit metadata; offset 5 or greater emits an empty list with 5 omitted. This catches restarting the offset per row.
- On that fixture, minimum length 2 with cap 1 and offset 1 emits `(5,0,3)` with 2 omitted; maximum length 2 with cap 1 and offset 1 emits `(2,0,2)` with 2 omitted. Conflicting length cutoffs, identical images, or tolerance 20 produce an empty list with zero omitted. Full horizontal count remains 5 and longest interval remains `(0,1,4)` when requested. Metrics, bounds, vertical diagnostics, verdict and exit status agree with the equivalent comparison without paging, under default failure and a passing aggregate budget. A nonzero-origin crop keeps interval coordinates crop-relative. RGBA cases cover alpha-only mismatches and stored RGB beneath zero alpha; adjacent differing delta magnitudes still form one interval before paging.
- Text and JSON describe the same page and explicit offset. Omitting the offset preserves the existing capped and uncapped report schema and text. Negative, fractional, malformed, non-ASCII and missing offsets exit 2 with empty stdout. Offset without a cap, including explicit zero, fails before image reads and names both flags; cap plus offset without the list flag also fails before image reads. Direct-script and package invocations agree. Help and README explain dependencies, filter-before-offset ordering, omitted-count semantics and full-list memory use; the invariant register names the new tests, and `make check` passes after final edits.

### Split cursor apply orchestration by lifecycle (planned 2026-11-04 by the organize role)

**Goal and cost.** `tools/apply_cursor.py` currently combines home resolution, installed-theme validation and Xcursor link setup, external desktop selection, and apply/remove orchestration. The low-level link operations already live in `tools/cursor_link.py`, while config inspection lives in `tools/cursor_config.py`; keeping lifecycle coordination in the CLI module makes it harder to follow the apply and removal guarantees independently.

**Target structure and files.** Add `tools/cursor_selection.py` for selector availability, scratch-log execution, and its optional-selector behavior, moving `_select` there. Add `tools/cursor_workflow.py` for apply/remove orchestration and the related state transitions: move `_apply` and `_remove` there, keeping the installed-data lock across revalidation, link installation, and selection, and retaining removal's lock-free path when the data home is absent. Keep `resolve_homes`, CLI parsing/diagnostics, and `main` in `tools/apply_cursor.py`; keep filesystem link mechanics in `tools/cursor_link.py` and config reading in `tools/cursor_config.py`. Update imports, tests, and documentation references for moved functions. Files expected: `tools/apply_cursor.py`, new `tools/cursor_selection.py`, new `tools/cursor_workflow.py`, `tests/test_apply_cursor.py`, `tests/test_apply_cursor_locks.py`, and any docstrings that name the old function locations.

**Acceptance criteria.** Direct-script and package entry points retain current behavior and diagnostics. The selection module owns only selector invocation; the workflow module owns apply/remove state transitions and lock scope; the CLI module owns argument handling and home resolution. Tests call the new module paths and cover optional selector handling, lock-protected revalidation, and removal with a missing data home. Grep of source, tests, and Markdown finds no stale references to the moved function paths. `make check` passes.

### Reference-pixel sampler: cap the vertical color-match interval report (planned 2026-11-04 by the plan role) — done 2026-11-04 by the feature role

**Goal.** Bound noisy `--find-color --match-column-runs` output while retaining full-region measurements. Source and archive-heading searches found vertical length filters and counts, and horizontal output caps, but no vertical color-match interval cap. This complements the preceding horizontal-cap entry and can merge independently: the vertical filter and report blocks already exist.

**Approach and files.** In `tools/sample_arguments.py::build_parser`, add optional `--max-match-column-runs N`, default None, using `positive_int`; `option_error` requires `--match-column-runs`. In `tools/sample_report_search.py::_search_match`, slice the completed column-major list after both inclusive vertical length filters and add `match.omitted_column_runs` (eligible count minus emitted count) when the cap is explicit, including zero. In `report_search`, print `omitted matching column runs: N` immediately after the vertical list. Keep `tools/sample_match_runs.py::_MatchRuns` unchanged: its count and longest summary precede report filtering, and `finish` sorts by `(x,y)`. This bounds output, not segmentation memory. Add `tests/test_sample_match_column_runs_limit.py` using `CliTestCase` and the generated PNG pattern in `TestSampleMatchColumnRunsMaxLength`; document the flag beside vertical filters in README.md and extend the vertical-filter tooling row in docs/invariants.md. These five changed files constitute one run; pagination and collector optimization are outside this plan.

**Acceptance criteria.**

- For a 2x9 crop at absolute origin (2,1), column zero matches relative rows {0,2,3,5,6,7} and column one matches {8}. Cap 2 emits exactly `(2,1,1)` and `(2,3,2)` as `{x,y,length}` records with 2 omitted. Cap 3 adds `(2,6,3)` with 1 omitted, detecting a cap restarted per column. Maximum length 2 plus cap 2 emits the leading pair with 1 omitted; minimum length 2 plus cap 1 emits `(2,3,2)` with 1 omitted. Contradictory length cutoffs yield an empty list with zero omitted. Cap 4 or larger includes the bottom-flushed `(3,9,1)` and reports zero omitted; no matches produce an empty list with zero omitted.
- With summaries requested, count remains 7, column-run count remains 4 and longest column run remains `(2,6,3)` despite capping. Bounds, fraction, centroid, horizontal intervals, row/column diagnostics and coordinate paging match uncapped results. Include adjacent unequal RGB values accepted by tolerance and an exact-alpha rejection that splits an interval, checking literal capped records; stored RGB beneath alpha zero remains searchable. JSON and text expose the same prefix and omitted count. Without the option, neither the new member nor text line appears.
- Zero, negative, fractional, malformed, non-ASCII and missing caps exit 2 with empty stdout. A valid cap with `--find-color` but without `--match-column-runs` fails before reading a missing image and names the required flag. Help describes the dependency; direct-script and package output agree. README distinguishes interval count from pixel length and states filtering precedes capping; the invariant row names the new tests. `make check` passes after the final edit.
