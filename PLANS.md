### Reference-pixel sampler: count color matches per row (planned 2026-11-02 by the plan role)

**Goal and grounding.** Locate horizontal bands of a sampled color without dumping matching coordinates or intervals. `tools/sample_report_search.py::_search_match` already evaluates the RGB tolerance and exact-alpha predicate in one positioned traversal, but reports a whole-region count and optional coordinates, centroid and intervals rather than dense row counts. Searches of sampler code, tests and planned/finished plan text found no `--match-rows` capability; the finished horizontal and vertical matching-segment plans cover intervals instead. This work is independent of the waiting fidelity-axis extraction.

**Approach and files.** Add boolean `--match-rows` in `tools/sample_arguments.py::build_parser` and reject it without `--find-color` in `option_error`, before image reads. In `_search_match`, allocate a height-sized zero list only when requested and increment index `y - args.y` inside the existing accepted-match branch. Add `match.rows` to JSON only with the option. In `report_search`, append `matching rows: ` followed by the compact JSON integer array after existing optional interval lines. Array index zero denotes the requested region's first row; include zero-match rows. Reuse the predicate and traversal, without an image mask or another decode. Add `tests/test_sample_match_rows.py` using `support.cli_fixtures.CliTestCase`, document the flag beside color-search options in README.md, and add its guarantee to the sampler section of docs/invariants.md. These five files bound the implementation; no new dependency or theme asset is needed.

**Acceptance criteria.** An offset nonsquare fixture with outside-region matches, separated matching pixels and an empty interior row pins literal expected arrays in text/JSON; sum of row counts equals the full match count. Cover absent matches, full coverage, single row, single column and single pixel. Pin tolerance-boundary inclusion, exact-alpha exclusion, stored RGB under zero alpha and opaque fallback. Combine with `--match-pixels 1`, `--match-runs` and `--match-column-runs` to verify row counts still cover the complete region and existing fields retain their expected values. Assert default key/line omission, missing `--find-color` returns 2 with empty stdout before header/decode reads, help mentions the flag, and direct-script/package invocations agree. Spy on the positioned iterator to verify a single traversal and retain the existing `max_rows=y+height` decode bound. Run `make check` after final implementation and documentation edits; keep changes within a few hundred lines including tests.

### Fidelity diagnostics: report the centroid of mismatching pixels (planned 2026-11-02 by the plan role)

**Goal and grounding.** Locate the spatial centre of scattered rendering errors without treating their enclosing rectangle's midpoint as their centre. `tools/fidelity_spatial.py` reports row/column counts, bounds and runs; searches of fidelity code, tests and planned/finished plan text found no mismatch-centroid diagnostic. Finished centroid plans concern sampled colors instead. This feature is independent of the waiting sampler row-count plan.

**Approach and files.** Add boolean `--difference-centroid` in `tools/fidelity_cli_parser.py::build_parser`. Add `difference_centroid(candidate, reference, tolerance)` in `tools/fidelity_spatial.py`: in one row-major scan use `tools/fidelity_pixels.py::_absolute_deltas` to select pixels whose maximum raw RGBA delta strictly exceeds tolerance, accumulate integer coordinate sums and count, then return crop-relative `{"x": sum_x/count, "y": sum_y/count}` or `None` for zero mismatches. Each selected pixel has equal weight regardless of delta magnitude; coordinates are integer pixel indices without a half-pixel offset. Keep constant auxiliary space. Wire the opt-in call through `tools/fidelity.py::main` using both import modes. Extend `tools/fidelity_reports.py::report_data` with keyword-only `centroid=None` and `include_centroid=False`; when requested, include top-level `difference_centroid` even when its value is null. In `tools/fidelity_rendering.py::render_text`, test key presence and print `difference centroid: ` plus JSON of that value immediately before the verdict. Leave source-coordinate translation to callers adding each crop's origin. Add `tests/test_fidelity_centroid.py` following `tests/test_fidelity_row_bounds.py` and its `FidelityCliTestCase`; document the option in README.md's fidelity section and its guarantee in docs/invariants.md. These five tool modules, one focused test file and two documentation files bound the work; no new dependency or theme value is needed.

**Acceptance criteria.** Pin literal fractional means for a nonsquare asymmetric fixture with disconnected mismatches and different error magnitudes, distinguishing equal-pixel weighting from delta weighting and the bounds midpoint. Cover zero mismatches (explicit JSON/text null), a singleton, full coverage, tolerance-boundary exclusion, alpha-only errors, opaque alpha fallback and stored RGB beneath zero alpha. CLI fixtures with different nonzero candidate/reference crop origins exclude outside-crop errors and retain crop-relative means; show the same diagnostic on default failure and budget-allowed success, with verdicts matching runs without the option. Combine with row counts and runs to pin their expected outputs. Assert omitted key/line and no helper call without the flag, help text, package/direct-script parity, and existing error behavior for unreadable or differently sized inputs. Add a focused report/render assertion distinguishing requested-null from omission. Preserve bounded source reads and run `make check` after final implementation and documentation edits. Keep the implementation and tests within a few hundred changed lines.
