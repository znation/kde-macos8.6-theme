## Planned

### Fidelity diagnostics: page through horizontal mismatch intervals (planned 2026-11-04 by the plan role)

**Goal and grounding.** Inspect later horizontal mismatch segments without printing the preceding intervals. `tools/fidelity.py::_filter_run_report` currently takes a prefix after length filtering; `main` computes full counts and longest summaries before that step. Searches of tools, tests, the queue and archive found no horizontal difference-run offset capability or plan. The finished horizontal-cap plan explicitly leaves pagination out of scope. This entry is independent of the waiting vertical reference-sampler plan.

**Approach and files.** Add optional `--difference-run-offset K` to `tools/fidelity_cli_parser.py::build_parser`, default None, with a dedicated nonnegative ASCII decimal converter in `tools/fidelity_arguments.py` patterned on `worst_pixel_offset`. In `tools/fidelity.py::main`, require `--max-difference-runs` for an explicit offset, including zero, before source reads; retain the cap's requirement for `--difference-runs`. Extend `_filter_run_report` with a default-zero offset and pass it only for the horizontal list: after both inclusive length filters skip K intervals globally, then emit at most the cap. Omitted count remains eligible count minus emitted count, including skipped and trailing intervals. Thread optional `difference_run_offset` through `tools/fidelity_reports.py::report_data`; explicit offsets add that top-level JSON integer. In `tools/fidelity_rendering.py::render_text`, print `difference run offset: K` immediately before the horizontal list. Preserve absent-option output and full-data summaries; this limits output, not segmentation memory. Add `tests/test_fidelity_difference_runs_offset.py` using `FidelityCliTestCase` and generated PNGs patterned on `TestDifferenceRunsLimit`. Document beside the horizontal cap in README.md and extend its docs/invariants.md row. The small parser, slicing and report additions plus focused tests fit one run; vertical pagination is separate work.

**Acceptance criteria.**

- Against a black 9x2 reference, red-channel delta 20 at x={0,2,3,5,6,7} in row zero and x={0,1,2,3,8} in row one produces five intervals. Cap 2 with offset 2 emits exactly `(5,0,3)` and `(0,1,4)` as `{x,y,length}` records, with 3 omitted and `difference_run_offset=2`. Offset zero emits the capped prefix with explicit offset metadata; offset 5 or larger emits an empty list with 5 omitted. These expectations catch an offset restarted per row.
- On that fixture, minimum length 2 with cap 1 and offset 1 emits `(5,0,3)` with 2 omitted; maximum length 2 with cap 1 and offset 1 emits `(2,0,2)` with 2 omitted. Conflicting cutoffs, identical images, or tolerance 20 yield an empty page with zero omitted. Full horizontal count stays 5 and longest summary stays `(0,1,4)` for the unfiltered mismatch fixture. Metrics, bounds, verdict, exit status and requested vertical diagnostics agree with the corresponding unpaged comparison, under both default failure and a passing aggregate budget. A nonzero-origin crop retains crop-relative page coordinates; alpha-only mismatches and differing stored RGB beneath zero alpha participate before paging.
- Text and JSON describe the same page and offset. Omitting the offset preserves capped and uncapped report fields and lines. Negative, fractional, signed, whitespace-padded, malformed, non-ASCII and missing values exit 2 with empty stdout. An offset without a cap fails before opening nonexistent images and names both flags; cap plus offset without the list flag also fails before reads. Help and README describe dependencies, filter-before-offset ordering, omitted-count semantics and the memory limitation. Package and direct-script invocations agree, the invariant register names the new tests, and `make check` passes after final edits.


### Fidelity diagnostics: page through vertical mismatch intervals (planned 2026-11-04 by the plan role)

**Goal and grounding.** Inspect later vertical mismatch segments without printing earlier intervals. `tools/fidelity.py::_filter_run_report` already accepts an offset for horizontal reports, but `main` supplies none for vertical reports. Searches of tools, tests, Planned entries and finished-plan headings found no vertical mismatch offset capability or plan; the archived vertical-cap plan explicitly excludes pagination. This is separate from the queued horizontal entry and uses the already implemented horizontal paging support.

**Approach and files.** Add optional `--difference-column-run-offset K`, default None, to `tools/fidelity_cli_parser.py::build_parser`, with a dedicated nonnegative ASCII decimal converter in `tools/fidelity_arguments.py` following `difference_run_offset`. In `tools/fidelity.py::main`, reject an explicit offset (including zero) without `--max-difference-column-runs` before image reads; keep the cap's existing list-flag dependency. Pass the offset to `_filter_run_report` for the vertical list: both inclusive length filters precede skipping K eligible intervals globally in column-major order. Keep full counts and longest summaries computed before selection. Thread optional top-level integer `difference_column_run_offset` through `tools/fidelity_reports.py::report_data`; in `tools/fidelity_rendering.py::render_text`, print `difference column run offset: K` immediately before the vertical list. Omitted count remains eligible count minus emitted count, including skipped and trailing intervals. Add `tests/test_fidelity_column_runs_offset.py` using `FidelityCliTestCase` and generated PNGs patterned on `TestDifferenceRunsOffset`; document beside the vertical cap in README.md and extend the vertical-run guarantees in docs/invariants.md. These small additions fit one run; segmentation still retains its full list.

**Acceptance criteria.**

- Against a black 2x9 reference, red-channel delta 20 at y={0,2,3,5,6,7} in column zero and y={0,1,2,3,8} in column one produces five vertical intervals. Cap 2 with offset 2 emits exactly `(0,5,3)` and `(1,0,4)` as `{x,y,length}` records, with 3 omitted and `difference_column_run_offset=2`. Offset zero emits the capped prefix with explicit metadata; offset 5 or larger emits an empty list with 5 omitted. This catches restarting the offset at each column.
- On that fixture, minimum length 2 with cap 1 and offset 1 emits `(0,5,3)` with 2 omitted; maximum length 2 with cap 1 and offset 1 emits `(0,2,2)` with 2 omitted. Conflicting cutoffs, identical images, or tolerance 20 produce an empty page with zero omitted. Requested unfiltered vertical count remains 5 and longest-column summary remains `(1,0,4)` on the original mismatch fixture. Metrics, bounds, verdict and exit status agree with the equivalent unpaged comparison under default failure and a passing aggregate budget. Combined horizontal and vertical paging produce independent pages and omitted counts; a nonzero-origin crop retains crop-relative coordinates. Alpha-only differences and stored RGB differences beneath zero alpha are included before paging.
- Text and JSON describe the same page and explicit offset; absent offsets add neither metadata nor a text line and preserve the existing capped and uncapped results. Negative, signed, fractional, whitespace-padded, malformed, non-ASCII and missing offset values exit 2 with empty stdout. Offset without a cap, including zero, fails before reading nonexistent images with a diagnostic naming both flags; cap plus offset without the vertical-list flag also fails before reads. Direct-script and package invocations agree. Help and README explain dependencies, filter-before-offset ordering, omitted-count semantics and the output-only memory bound; the invariant register names the tests, and `make check` passes after final edits.

### Reference-pixel sampler: cap the vertical color-match interval report (planned 2026-11-04 by the plan role) — done 2026-11-04 by the feature role

**Goal.** Bound noisy `--find-color --match-column-runs` output while retaining full-region measurements. Source and archive-heading searches found vertical length filters and counts, and horizontal output caps, but no vertical color-match interval cap. This complements the preceding horizontal-cap entry and can merge independently: the vertical filter and report blocks already exist.

**Approach and files.** In `tools/sample_arguments.py::build_parser`, add optional `--max-match-column-runs N`, default None, using `positive_int`; `option_error` requires `--match-column-runs`. In `tools/sample_report_search.py::_search_match`, slice the completed column-major list after both inclusive vertical length filters and add `match.omitted_column_runs` (eligible count minus emitted count) when the cap is explicit, including zero. In `report_search`, print `omitted matching column runs: N` immediately after the vertical list. Keep `tools/sample_match_runs.py::_MatchRuns` unchanged: its count and longest summary precede report filtering, and `finish` sorts by `(x,y)`. This bounds output, not segmentation memory. Add `tests/test_sample_match_column_runs_limit.py` using `CliTestCase` and the generated PNG pattern in `TestSampleMatchColumnRunsMaxLength`; document the flag beside vertical filters in README.md and extend the vertical-filter tooling row in docs/invariants.md. These five changed files constitute one run; pagination and collector optimization are outside this plan.

**Acceptance criteria.**

- For a 2x9 crop at absolute origin (2,1), column zero matches relative rows {0,2,3,5,6,7} and column one matches {8}. Cap 2 emits exactly `(2,1,1)` and `(2,3,2)` as `{x,y,length}` records with 2 omitted. Cap 3 adds `(2,6,3)` with 1 omitted, detecting a cap restarted per column. Maximum length 2 plus cap 2 emits the leading pair with 1 omitted; minimum length 2 plus cap 1 emits `(2,3,2)` with 1 omitted. Contradictory length cutoffs yield an empty list with zero omitted. Cap 4 or larger includes the bottom-flushed `(3,9,1)` and reports zero omitted; no matches produce an empty list with zero omitted.
- With summaries requested, count remains 7, column-run count remains 4 and longest column run remains `(2,6,3)` despite capping. Bounds, fraction, centroid, horizontal intervals, row/column diagnostics and coordinate paging match uncapped results. Include adjacent unequal RGB values accepted by tolerance and an exact-alpha rejection that splits an interval, checking literal capped records; stored RGB beneath alpha zero remains searchable. JSON and text expose the same prefix and omitted count. Without the option, neither the new member nor text line appears.
- Zero, negative, fractional, malformed, non-ASCII and missing caps exit 2 with empty stdout. A valid cap with `--find-color` but without `--match-column-runs` fails before reading a missing image and names the required flag. Help describes the dependency; direct-script and package output agree. README distinguishes interval count from pixel length and states filtering precedes capping; the invariant row names the new tests. `make check` passes after the final edit.
