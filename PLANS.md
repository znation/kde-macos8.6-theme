### Reference-pixel sampler: cap the horizontal color-match interval report (planned 2026-11-04 by the plan role)

**Goal and grounding.** Keep noisy `--find-color --match-runs` searches readable by bounding the displayed interval list. Searches of source, Planned entries and finished-plan headings found length filters, coordinate pagination and scanline color-run caps, but no horizontal color-match interval count cap. This is independent of the waiting fidelity vertical-cap plan: it changes the sampler's parser and report, not the fidelity tool.

**Approach and files.** In `tools/sample_arguments.py::build_parser`, add optional `--max-match-runs N`, default None, using `positive_int`; `option_error` requires `--match-runs` when supplied. In `tools/sample_report_search.py::_search_match`, take the first N eligible horizontal intervals after both inclusive length filters, recording eligible count minus emitted count as `match.omitted_runs` when the cap is explicit, including zero. In `report_search`, print `omitted matching runs: N` immediately after the horizontal list. Preserve the full-search summaries already accumulated by `tools/sample_match_runs.py::_MatchRuns`; retain existing interval allocation and describe this as an output bound. Add `tests/test_sample_match_runs_limit.py` following `TestSampleMatchRunsMaxLength` and its generated cropped PNG fixture. Document the option beside horizontal match-length filters in README.md and extend the corresponding tooling guarantee in docs/invariants.md. These five changed files form one implementation run; vertical limits, pagination and streaming allocation are separate work.

**Acceptance criteria.**

- For the existing 9x2 search region at absolute origin (2,1), with matches at relative x={0,2,3,5,6,7} on row zero and x={0,1,2,3,8} on row one, cap 2 emits exactly `(2,1,1)` and `(4,1,2)` as `{x,y,length}` records with 3 omitted. Cap 4 includes the first row's three intervals and row one's `(2,2,4)`, with 1 omitted, detecting a cap restarted per row. Minimum length 2 plus cap 1 emits `(4,1,2)` with 2 omitted; maximum length 2 plus cap 2 emits the original leading pair with 1 omitted. Contradictory cutoffs yield an empty list with zero omitted.
- Cap 5 or larger emits the complete eligible list with zero omitted; a target absent from the crop produces an empty list with zero omitted. Requested full run count remains 5, longest run remains `(2,2,4)`, and match count remains 11 despite capping. Bounds, fraction, centroid, row/column diagnostics, vertical intervals and coordinate paging agree with the uncapped search. Tolerance and exact-alpha predicates determine eligible intervals before capping, including stored RGB beneath zero alpha. Text and JSON show the same prefix and omitted count; omitting the option adds neither the new key nor text line.
- Zero, negative, fractional and non-ASCII caps, and a missing value, exit 2 with empty stdout. A valid cap with `--find-color` but without `--match-runs` fails before reading a missing image, naming the required flag. Help describes the dependency; package and direct-script invocations agree. README distinguishes interval count from pixel length and states filtering precedes capping; the invariant register names the tests. `make check` passes after the final edit.
