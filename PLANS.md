### Fidelity diagnostics: count horizontal mismatch segments (planned 2026-11-03 by the plan role) — done 2026-11-03 by the feature role

**Goal.** Quantify fragmentation of a rendered border defect with a scalar instead of printing its complete interval list. Implemented as specified.

**Approach and files.** Added the streaming counter, CLI/report wiring, focused tests, README documentation and dated invariant. Requested run lists provide the pre-filter count.

**Acceptance criteria.** Implemented count-only streaming and requested-list reuse; focused and project checks verify behavior.
- Compared 4x3 crops with over-tolerance masks `1101`, `0000`, `1111` produce JSON `difference_run_count=3`, text `difference run count: 3`, and `metrics.differing=7`. The requested horizontal list has lengths 2, 1, 4; minimum length 3 or maximum length 1 each leaves one listed segment while count remains 3. Contradictory cutoffs empty the list while count stays 3. Distinct nonzero candidate/reference crop origins select these masks without including surrounding mismatches.
- Identical crops report 0; fully differing 3x2 crops report 2, fully differing 1x3 crops report 3, and a differing single pixel reports 1. Runs at opposite row edges stay separate and a last-row right-edge run is counted. Adjacent differing pixels with unequal delta magnitudes form one segment. A delta equal to tolerance is excluded, and tolerance 255 yields zero. Alpha-only differences, missing alpha as 255, and stored RGB beneath zero alpha follow the existing raw RGBA predicate.
- Count-only reports omit horizontal and vertical interval arrays. Omitting the flag omits the new field and line and does not invoke the counter. Focused coverage rejects full-list collection during count-only mode and rejects an extra counter scan when the horizontal list is requested, including an empty list. Combining count, longest-run, vertical-list and worst-pixel paging options preserves their separately expected values; comparison metrics, verdict and exit status agree with the same invocation without the count flag, on passing and failing comparisons. Text/JSON, package/direct-script invocations and help expose the same option. Run `make check` after final edits.

### Fidelity diagnostics: count horizontal mismatch segments (planned 2026-11-03 by the plan role)

**Goal.** Quantify scattered rendering errors without emitting a potentially large interval list. Source and related archive searches found horizontal mismatch lists and longest-run summaries, but no scalar segment count. This is independent of the queued sampler matching-segment count.

**Approach and files.** Add boolean `--difference-run-count` in `tools/fidelity_cli_parser.py::build_parser`, usable without `--difference-runs`. Add `count_difference_runs(candidate, reference, tolerance)` in `tools/fidelity_spatial.py`, counting the existing `_iter_difference_axis_runs(..., vertical=False)` lazily without retaining intervals. In `tools/fidelity.py::main`, when requested, take the length of an already requested horizontal run list before its min/max length filters, otherwise call the new helper; preserve both import paths. Pass an optional `run_count` to `tools/fidelity_reports.py::report_data` and emit top-level JSON `difference_run_count` when it is not None, including zero. In `tools/fidelity_rendering.py::render_text`, print `difference run count: N` immediately before the optional horizontal run list, using the existing diagnostic loop. Add focused unit and CLI cases in `tests/test_fidelity_run_count.py`, patterned on `TestLongestDifferenceRun` and `FidelityCliTestCase`; document the flag in README.md and add its tooling guarantee in docs/invariants.md. Keep this to one scalar diagnostic, roughly a few hundred changed lines including tests; no vertical counterpart or scan-fusion redesign.

**Acceptance criteria.**
- A 4x3 compared crop with over-tolerance masks `1101`, `0000`, `1111` reports JSON `difference_run_count: 3` and text `difference run count: 3`, while differing-pixel count is 7. Nonzero, distinct candidate/reference crop origins produce the same scalar. With horizontal lists enabled, the crop-relative records start at (0,0), (3,0), (0,2) with lengths 2,1,4. Minimum length 3 or maximum length 1 leaves one listed run while the count remains 3; contradictory cutoffs empty the list while retaining count 3. Longest-run output and comparison metrics agree with their uncombined results.
- Identical images report zero; fully differing 3x2 and 1x3 images report 2 and 3 respectively; a differing single pixel reports 1. Adjacent matches across row boundaries remain separate. Adjacent mismatches of unequal delta magnitude form one run, a delta exactly equal to tolerance separates runs, and tolerance 255 reports zero. Alpha-only mismatches and stored RGB beneath zero alpha count; absent alpha is treated as 255 in either operand.
- Count-only JSON/text omit run arrays. Omitting the flag omits its field and line. Count-only operation remains usable when the list-producing collector is patched to fail; combined list/count operation remains usable when the new image-based count helper is patched to fail, including empty lists. Help lists the flag, direct-script and package invocations agree, and passing/failing comparisons retain their exit statuses with the diagnostic enabled. Run `make check` after final edits.

### Reference-pixel sampler: page through ranked histogram colors (planned 2026-11-03 by the plan role) — done 2026-11-03 by the feature role

**Goal.** Inspect later palette entries without increasing the displayed palette or changing the crop. The existing histogram filters and `--top-colors` select a leading page; source and archive searches found coordinate pagination and worst-pixel pagination, but no histogram offset.

**Approach and files.** Add optional `--color-offset K`, default None, in `tools/sample_arguments.py::build_parser`, with a nonnegative plain ASCII integer converter in `tools/sample_validators.py` patterned on `match_pixel_offset`. In `option_error`, immediately after the existing top-colors check, require `--top-colors` for explicit offset use, including zero; the existing top-colors check continues to require histogram mode. In `tools/sample_report_histogram.py::_histogram_result`, apply exclusions and count/fraction filters before ranking by descending count then ascending RGB/RGBA tuple. Select the first `min(K + N, len(counts))` candidates with the existing heap selection and retain slice `[K:K + N]`, where N is the top-colors limit. Preserve original `total_colors` and calculate omitted pixels as region area minus emitted counts, including filtered, skipped and trailing colors. Report offset metadata only when the option is explicitly used. Spatial diagnostics continue to describe emitted colors using their complete region occurrences. Add `tests/test_sample_histogram_offset.py`, extend `tests/test_sample_option_validation.py::TestSampleOptionValidation`, and document pagination and selection storage (offset plus limit, bounded by distinct-color count) in README.md and docs/invariants.md. This is one bounded option across seven files, at most a few hundred changed lines; decoding and theme artwork stay outside its scope.

**Acceptance criteria.** Given an offset eight-pixel crop with RGB counts 3, 2, 2 and 1, `--top-colors 2 --color-offset 1` emits the two count-2 colors in ascending tuple order, with `total_colors=4` and `omitted_pixels=4`; offset 3 emits the count-1 color and omits seven pixels, and offsets 4 and 100 return an empty palette and omit eight. Excluding the count-3 color before offset 1 yields the later count-2 tuple followed by the count-1 tuple; count and fraction cutoffs likewise operate before pagination. Explicit zero matches the existing first-page report, and omitting the option preserves existing output. Fractions retain denominator eight; positions, bounds and centroids remain absolute and cover every occurrence of each emitted color. An RGBA fixture verifies opacity participates in tie order and grouping, including stored RGB under zero alpha, while RGB mode merges opacity variants and opaque input uses alpha 255. Text and JSON agree on selected colors and totals; package and direct-script invocations agree. Negative, fractional, exponent, underscore, whitespace, non-ASCII, nonnumeric and missing offsets exit 2 with empty stdout before PNG reads. Explicit offset without top-colors, including zero in histogram mode, reports `--color-offset requires --top-colors`; top-colors outside histogram retains its existing diagnostic precedence. An integer beyond Python's conversion limit fails without a traceback, while a large valid offset returns an empty page. Run `make check` after final edits.
