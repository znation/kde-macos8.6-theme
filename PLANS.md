### Fidelity diagnostics: cap the vertical mismatch-run report (planned 2026-11-04 by the plan role)

**Goal and grounding.** Bound the printed vertical mismatch intervals for noisy candidate comparisons. Source and archive searches found vertical length filters and full-count/longest summaries, but no vertical list-count cap. The finished horizontal-cap plan explicitly excludes vertical capping. This is independently mergeable from the queued horizontal entry: it adds a separate option and report field.

**Approach and files.** In `tools/fidelity_cli_parser.py::build_parser`, add optional `--max-difference-column-runs N`, default None, using `positive_int`. In `tools/fidelity.py::main`, reject it without `--difference-column-runs` before image reads. After both vertical length filters, slice the eligible column-major list to its first N records and compute eligible count minus emitted count. Keep requested count and longest-column calculations before filtering and capping. Pass an optional `omitted_difference_column_runs` keyword through `tools/fidelity_reports.py::report_data`; explicit capping adds that top-level JSON integer, including zero. `tools/fidelity_rendering.py::render_text` prints `omitted difference column runs: N` immediately after the vertical list. Retain the existing full-list allocation; this bounds output, not segmentation memory. Add `tests/test_fidelity_column_runs_limit.py` using `FidelityCliTestCase` and generated PNGs, following the fixture in `TestColumnRunsMaximumLength`. Document the option beside vertical length filters in README.md and extend the vertical-run tooling guarantees in docs/invariants.md. These seven files comprise one small implementation run; pagination and streaming allocation are out of scope.

**Acceptance criteria.**

- Against a black 2x9 reference, a candidate with red-channel delta 20 at y={0,2,3,5,6,7} in column 0 and y={0,1,2,3,8} in column 1 has five intervals. Limit 2 emits exactly `(0,0,1)` and `(0,2,2)` as `{x,y,length}` records, with 3 omitted. Minimum length 2 plus limit 1 emits `(0,2,2)` with 2 omitted; maximum length 2 plus limit 2 emits the original two leading intervals with 1 omitted. Limit 4 emits the first four intervals across both columns with 1 omitted, catching a cap restarted per column. Contradictory length cutoffs yield an empty list and zero omitted.
- Limit 5 or larger emits the complete eligible list with zero omitted. Identical images, or tolerance 20 on this fixture, yield an empty list with zero omitted. Requested full vertical count stays 5 and longest-column summary stays `(1,0,4)` despite capping. Metrics, bounds, verdict and exit status match an uncapped comparison under default failure and a passing aggregate budget. A nonzero-origin crop retains crop-relative coordinates; alpha-only mismatches obey the cap too. Combined horizontal and vertical caps produce independent lists and omitted counts. Text and JSON describe the same vertical intervals and omitted count. Omitting the option adds neither the new key nor text line.
- Zero, negative, fractional and non-ASCII limits, and a missing value, exit 2 with empty stdout. A valid cap without the vertical list flag fails before image access with a diagnostic naming both flags. Help describes the dependency; package and direct-script invocations agree. README explains filtering before capping and the output-only bound, the invariant register names the new tests, and `make check` passes after the final edit.
