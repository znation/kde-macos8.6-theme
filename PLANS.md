## Planned

### Reference-pixel histogram: report each emitted color's centroid (planned 2026-11-02 by the plan role) — done 2026-11-02 by the feature role

**Goal and grounding.** Measure the spatial centre of several palette colors in one reference region without repeating single-color searches. `tools/sample_report_histogram.py::_histogram_result` already counts colors and optionally traverses coordinates for bounds and first positions; `tools/sample_report_search.py::_search_match` offers a centroid for one search target. Searches of sampler source, tests and planned/finished entries for histogram/color centroids found no equivalent histogram option. This is independent of the waiting fidelity report mapping plan.

**Approach and files.** Add boolean `--color-centroids` in `tools/sample_arguments.py::build_parser`, requiring `--histogram` through `option_error` before image reads. In `_histogram_result`, accumulate integer x/y sums for emitted colors during the existing optional positioned traversal, enabling that traversal for centroids too. Divide by each color's full region count and append `centroid: {x, y}` to its JSON record. In `report_histogram`, append `  centroid=X,Y` after existing text suffixes, using ordinary Python float formatting. Use absolute integer pixel indices without a half-pixel offset; group by RGB normally and exact RGBA with `--alpha`. Retain sums only for emitted colors under `--top-colors`, while including every occurrence of those colors in the requested region. Add no per-color rescans or stored coordinate lists. Touch these two tool files, new `tests/test_sample_histogram_centroids.py`, the histogram documentation in `README.md` outside the brief, and a new sampler guarantee row in `docs/invariants.md`.

### Reference-pixel search: isolate matching-interval bookkeeping (planned 2026-11-02 by the plan role)

**Goal and grounding.** Separate horizontal and vertical interval state from color matching and statistics in `tools/sample_report_search.py::_search_match`. It currently owns row transitions, horizontal run starts, per-column starts, terminal flushing and column sorting alongside bounds, centroid and coordinate collection. Source and archive searches found the interval features and report-handler extraction, but no separate interval accumulator. This maintenance change is independent of the queued histogram-centroid plan.

**Approach and files.** Add `tools/sample_match_runs.py::_MatchRuns`, initialized with the region and the two existing interval-enable flags. Move the current interval bookkeeping into `observe(x, y, matches)` and `finish()`, called once per visited pixel and once after traversal respectively. `finish()` returns horizontal and vertical lists; retain current row-major horizontal order and `(x, y)` vertical sorting. Keep RGB tolerance, alpha consumption, count, bounds, centroid, coordinate limits, result-field inclusion and presentation in `_search_match`/`report_search`; pass the already-computed boolean to the helper. Preserve the single positioned traversal, without retaining a pixel mask or introducing rescans. Use the existing package/direct-script import convention. Touch the two tool files, extend `tests/test_sample_match_runs.py` and `tests/test_sample_match_column_runs.py`, and amend the two matching-run provenance cells in `docs/invariants.md` to name the helper while retaining their guarantees. No CLI or output-schema change.

**Acceptance criteria.** Existing interval tests retain their expected output. Add cropped fixtures covering a horizontal interval ending at a row edge immediately followed by a matching next-row first pixel, and vertical intervals still open at the region bottom in multiple columns; assert exact absolute interval lists. Cover both flags together, each alone, neither, empty matches and a fully matching rectangle, including text and JSON results. A combined-flags regression with tolerance, exact-alpha filtering and a coordinate limit asserts full-region intervals and count, and spies on `_positioned_region_pixels` to confirm one traversal. Check direct-script/package CLI parity using the suite's fixture conventions. Keep the extraction and tests within a few hundred lines and run `make check` after final edits. No new dependency or new feature is part of this plan.
