## Planned

### Reference-pixel sampler: page through vertical color-match intervals (planned 2026-11-04 by the plan role)

**Goal and grounding.** Inspect later vertical border segments without printing the preceding intervals. `tools/sample_report_search.py::_search_match` currently slices the filtered vertical list from its beginning; `tools/sample_match_runs.py::_MatchRuns.finish` orders that list by column then row. Searches for vertical match-offset spellings in tools, tests, the queue and archive found no existing option or plan. This is independently mergeable alongside the queued horizontal paging plan: both use existing caps, and this entry changes the vertical report blocks.

**Approach and files.** Add optional `--match-column-run-offset K` to `tools/sample_arguments.py::build_parser`, parsed with `plain_number` as a nonnegative ASCII integer. In `option_error`, require `--max-match-column-runs` for an explicit offset, including zero; retain the cap's list-mode and search dependencies. In `_search_match`, skip K eligible vertical intervals globally after both inclusive length filters, then emit at most the cap. Keep `omitted_column_runs` equal to eligible count minus emitted count, counting skipped and trailing intervals together. Explicit offsets add integer `match.column_run_offset`; `report_search` prints `matching column run offset: K` immediately before the vertical list. Absent offsets preserve existing output. Leave segmentation and full-region summaries intact; paging limits output, not interval collection memory. Add `tests/test_sample_match_column_runs_offset.py` using `CliTestCase` and generated PNGs following `TestSampleMatchColumnRunsLimit`, extend `tests/test_sample_option_validation.py::TestSampleOptionValidation`, document the option beside the vertical cap in README.md, and extend the vertical match-filter row in docs/invariants.md. These six files and a small report change fit one implementation run.

**Acceptance criteria.**

- For a 2x9 crop at (2,1), target matches at relative rows `{0,2,3,5,6,7}` in column zero and `{0,1,2,3,8}` in column one produce five vertical intervals. Cap 2 and offset 2 emit exactly `(2,6,3)` then `(3,1,4)` as `{x,y,length}` records, with 3 omitted and `column_run_offset=2`. Offset zero emits the capped prefix with explicit offset metadata; offset 5 or greater emits an empty list with 5 omitted. This detects an offset incorrectly restarted per column.
- On that fixture, minimum length 2 with cap 1 and offset 1 emits `(2,6,3)` with 2 omitted; maximum length 2 with cap 1 and offset 1 emits `(2,3,2)` with 2 omitted. Contradictory cutoffs or an absent target emit an empty list with zero omitted. Full-region match count stays 11, vertical interval count 5 and longest vertical interval `(3,1,4)`; requested bounds, fraction, centroid, coordinate page and horizontal diagnostics agree with the same search without vertical paging. A tolerance fixture verifies adjacent unequal accepted RGB values merge before paging; an exact-alpha fixture verifies rejected opacity splits intervals before paging, including stored RGB under zero alpha.
- Text and JSON describe the same page and offset; omitting the option preserves capped and uncapped output. Negative, fractional, malformed, non-ASCII and missing offsets exit 2 with empty stdout. An offset without a cap fails before opening a nonexistent image and names both flags; cap plus offset without required list/search mode also fails before image reads. Help and README explain filter-before-offset ordering, omitted-count semantics and the memory limitation. Direct-script and package invocations agree, the invariant register names the tests, and `make check` passes after final edits.

## Done

### Reference-pixel sampler: cap the vertical color-match interval report (planned 2026-11-04 by the plan role) — done 2026-11-04 by the feature role

**Goal.** Bound noisy `--find-color --match-column-runs` output while retaining full-region measurements. Source and archive-heading searches found vertical length filters and counts, and horizontal output caps, but no vertical color-match interval cap. This complements the preceding horizontal-cap entry and can merge independently: the vertical filter and report blocks already exist.

**Approach and files.** In `tools/sample_arguments.py::build_parser`, add optional `--max-match-column-runs N`, default None, using `positive_int`; `option_error` requires `--match-column-runs`. In `tools/sample_report_search.py::_search_match`, slice the completed column-major list after both inclusive vertical length filters and add `match.omitted_column_runs` (eligible count minus emitted count) when the cap is explicit, including zero. In `report_search`, print `omitted matching column runs: N` immediately after the vertical list. Keep `tools/sample_match_runs.py::_MatchRuns` unchanged: its count and longest summary precede report filtering, and `finish` sorts by `(x,y)`. This bounds output, not segmentation memory. Add `tests/test_sample_match_column_runs_limit.py` using `CliTestCase` and the generated PNG pattern in `TestSampleMatchColumnRunsMaxLength`; document the flag beside vertical filters in README.md and extend the vertical-filter tooling row in docs/invariants.md. These five changed files constitute one run; pagination and collector optimization are outside this plan.

**Acceptance criteria.**

- For a 2x9 crop at absolute origin (2,1), column zero matches relative rows {0,2,3,5,6,7} and column one matches {8}. Cap 2 emits exactly `(2,1,1)` and `(2,3,2)` as `{x,y,length}` records with 2 omitted. Cap 3 adds `(2,6,3)` with 1 omitted, detecting a cap restarted per column. Maximum length 2 plus cap 2 emits the leading pair with 1 omitted; minimum length 2 plus cap 1 emits `(2,3,2)` with 1 omitted. Contradictory length cutoffs yield an empty list with zero omitted. Cap 4 or larger includes the bottom-flushed `(3,9,1)` and reports zero omitted; no matches produce an empty list with zero omitted.
- With summaries requested, count remains 7, column-run count remains 4 and longest column run remains `(2,6,3)` despite capping. Bounds, fraction, centroid, horizontal intervals, row/column diagnostics and coordinate paging match uncapped results. Include adjacent unequal RGB values accepted by tolerance and an exact-alpha rejection that splits an interval, checking literal capped records; stored RGB beneath alpha zero remains searchable. JSON and text expose the same prefix and omitted count. Without the option, neither the new member nor text line appears.
- Zero, negative, fractional, malformed, non-ASCII and missing caps exit 2 with empty stdout. A valid cap with `--find-color` but without `--match-column-runs` fails before reading a missing image and names the required flag. Help describes the dependency; direct-script and package output agree. README distinguishes interval count from pixel length and states filtering precedes capping; the invariant row names the new tests. `make check` passes after the final edit.
