### Remove the Platinum keyboard modifier swap independently (planned 2026-11-04 by the plan role)

**Goal.** Provide `make remove-keymap` and `python3 tools/apply_keymap.py --remove` so a user can clear the left Alt/Control swap without navigating System Settings or removing unrelated XKB options. README.md currently documents manual reversal; the archived README removal-guide plan covers that documentation, not an executable removal path. Searches of the helper, Makefile, Planned entries and related archive headings found no such command.

**Approach and files.** Extend `tools/apply_keymap.py::main` with `--remove` and pass the mode into `_apply`. Add a small option-filtering function beside `merge_option`: split comma-separated tokens, trim whitespace, discard blanks and every exact `OPTION` token, preserve the remaining tokens' order and duplicates. When the target token is absent, return success after the read without writing configuration or requesting a reload. When present, publish the filtered list through `_write_options`, retaining `ResetOldOptions=true` even for an empty Options value so KWin clears its previously active swap, then use `_reload`'s existing best-effort policy. Adjust reload notes and CLI/module documentation to describe a keyboard-option change accurately in either mode. Keep existing apply semantics. Add the public target, Python readiness guard and help entry in Makefile; it invokes removal directly without installation or aggregate apply. Update README.md's modifier paragraph and Removing the theme table, and extend the keyboard-options row in `docs/invariants.md`. This clears the named option even if it predated theme installation; it does not restore saved settings. No backup, transaction or concurrency subsystem is added.

**Tests.** Extend `tests/test_apply_keymap.py` using `StubTools` for removal success, no-op, required-command failures and reload fallback. Add a Make dry-run assertion there using the repository's existing subprocess test support; `tests/test_make_help.py::TestHelp` already checks public-target help and README coverage. Keep the implementation and tests to this single removal operation and its command/documentation wiring.

**Acceptance criteria.**

- Given `caps:escape,ctrl:swap_lalt_lctl,compose:ralt,ctrl:swap_lalt_lctl`, removal publishes `caps:escape,compose:ralt` and enabled options, then requests a session reload; whitespace and empty tokens are normalized, while similarly named options survive. Given only the swap, the resulting Options value is empty and ResetOldOptions remains true.
- Given an empty value or options without the exact swap token, removal exits 0 without configuration writes or reload attempts. Running removal again after a successful removal has the same no-op result. Other surviving option duplicates keep their order.
- A failed read exits 1 without writes; a failed Options or ResetOldOptions write exits 1 without reload. Missing required tools retain the existing exit-2 diagnostic. Missing or failing reload emitters leave successfully written removal in place, exit 0 and explain that the keyboard change takes effect at next login; a working fallback succeeds without a failure note.
- A dry run of `make remove-keymap` exposes the removal CLI and no install/apply recipe; help and README expose the command, its scope and lack of previous-setting restoration. Existing default apply tests and the updated invariants check pass with `make check` after the final edit.
