### Select the existing dialog captures through make render (planned 2026-11-04 by the plan role)

**Goal and grounding.** Allow contributors to capture each existing surface through the same Make entry point. Makefile's `render` recipe currently passes only `RENDER_OUTPUT`; `tools/render_surface.py::main` already supports checkbox, combobox, menu and GTK dialog flags. The archived README render-recipe plans document direct Python commands, rather than a Make mode selector. Searches of the queue, archive and render code found no `RENDER_MODE` interface. This is independent of the queued sampler change.

**Approach and files.** In Makefile, add `RENDER_MODE ?= calculator` and accept exactly one whitespace-delimited token from `calculator`, `checkbox-dialog`, `combobox-dialog`, `menu-dialog`, `gtk-dialog` (surrounding whitespace is allowed). Validate with Make string/list operations before the render recipe runs; reject empty, multiple and unknown tokens with a fixed diagnostic naming `RENDER_MODE` and its allowed values, without echoing the supplied value. Map accepted tokens to fixed literal CLI flags, with no flag for calculator; never interpolate the raw selector into a shell command. Keep flags before the existing `--` output separator. Extend `help` and update both README.md capture guides to demonstrate the selector and replace claims that Make supports only the calculator. Add `tests/test_render_make.py` using unittest and bounded subprocesses, following `tests/test_render_surface.py::test_make_render_passes_a_dash_leading_output_as_a_path`; use a recording Python stub that satisfies the existing version check and records the renderer's argv, avoiding live compositor launches. Add one tooling row in docs/invariants.md. Scope is these five files, a handful of tests and at most a few hundred lines; the renderer's CLI and capture lifecycle need no change.

**Acceptance criteria.**
- With no selector, the renderer receives the same arguments as today. Each explicit dialog token supplies exactly its corresponding `--*-dialog` flag followed by `--` and the requested output path. Explicit calculator supplies no dialog flag. A path containing spaces and a dash-leading path each remain one positional argument; the recording stub verifies actual argv, not just dry-run text.
- Empty, unknown and multiple-token selectors fail before the renderer starts, with a diagnostic naming the selector and allowed values. Hostile values containing shell punctuation, command substitutions or control bytes neither create a sentinel file nor echo those bytes in diagnostics. A swapped GTK/menu mapping fails the per-mode argv assertions. Surrounding whitespace around one valid token succeeds.
- `make help` lists the selector and default. Both capture guides show a Make dialog example and describe the existing 320x240 calculator and 480x360 dialog sizes and extra client requirements. Existing direct Python commands remain valid. `make check` passes after the final edit.
