### Fidelity diagnostics: count vertical mismatch segments (planned 2026-11-03 by the plan role)

**Goal.** Quantify fragmentation along rendered vertical borders without printing a potentially large interval list. Source and archive searches found vertical interval lists and longest-run summaries, but no fidelity vertical segment count; the finished sampler vertical count serves a different CLI.

**Approach and files.** Add boolean `--difference-column-run-count` in `tools/fidelity_cli_parser.py::build_parser`. Add `difference_column_run_count` in `tools/fidelity_spatial.py`, counting `_iter_difference_axis_runs(..., vertical=True)` without retaining intervals. Wire both import modes and `main` in `tools/fidelity.py`: only when the flag is requested, take the unfiltered `column_runs` length if that list was requested (including an empty list), otherwise use the streaming counter. Compute this before either column-run length filter. Existing longest-run scans can remain separate; no scan-fusion redesign is needed. Add optional keyword-only `column_run_count=None` to `tools/fidelity_reports.py::report_data`, emitting integer `difference_column_run_count` when supplied, including zero. In `tools/fidelity_rendering.py::render_text`, handle the existing column-run pair separately from the generic diagnostic loop, at its current position, printing `difference column run count: N` immediately before the optional column list. Add `tests/test_fidelity_column_run_count.py` using `support.fidelity_cli_case.FidelityCliTestCase`, following the horizontal count fixtures, and document the option in README.md and the tooling table in docs/invariants.md. This single diagnostic fits one run across eight files with a few hundred changed lines including tests.

**Acceptance criteria.**
- Compared 3x4 crops with row masks `101`, `101`, `001`, `101` report JSON `difference_column_run_count=3`, text `difference column run count: 3`, and seven differing pixels. The vertical list contains crop-relative starts (0,0), (0,3), (2,0) with lengths 2,1,4. Minimum column length 3 or maximum column length 1 each leaves one listed segment but count 3; contradictory cutoffs empty the list but retain count 3. Distinct nonzero candidate/reference crop origins select this mask without counting surrounding mismatches.
- Identical crops report zero; fully differing 3x2 crops report 3, fully differing 1x3 crops report 1, and one differing pixel reports 1. Column boundaries split runs, including runs at the last column's bottom edge. Adjacent mismatches with unequal delta magnitudes remain one run. Delta equal to tolerance is excluded and tolerance 255 produces zero. Alpha-only mismatches, missing alpha as 255, and stored RGB beneath zero alpha follow the existing raw RGBA predicate.
- Count-only reports omit interval arrays unless separately requested. Omission of the flag omits its field and line and skips counting. Focused tests reject full-list collection in count-only mode and an extra counter scan when the vertical list is requested, including an empty list. Combining horizontal count, longest-column summary, length filters and worst-pixel paging preserves their separately expected results. Comparison metrics, verdict and exit status agree with the invocation without the new flag on passing and failing inputs. Text/JSON and package/direct-script invocations agree, help exposes the flag, and the text count precedes the column list when both appear. Run `make check` after final edits.

### Reference-pixel sampler: cumulative displayed palette coverage (planned 2026-11-03 by the plan role)

**Goal.** Show how much of a sampled surface the displayed palette explains as colors accumulate, without making users sum individual fractions. Source and finished-plan searches found individual color fractions but no cumulative histogram diagnostic. This is independent of the waiting fidelity diagnostic.

**Approach and files.** Add boolean `--color-cumulative-fractions` in `tools/sample_arguments.py::build_parser` and require histogram mode in `option_error`, next to the existing color-fractions validation. In `tools/sample_report_histogram.py::_histogram_result`, after selection and pagination, accumulate integer counts over emitted colors in report order and add `cumulative_fraction` to each color as running count divided by full requested region area. Start at zero for each displayed page: excluded, filtered, skipped and trailing colors never contribute to the numerator. Use integer accumulation followed by division, avoiding accumulated float rounding; no additional image traversal is needed. In `report_histogram`, append `cumulative_fraction=VALUE` after the optional individual fraction and before position/centroid fields, using ordinary Python float formatting. The flag works independently of `--color-fractions`. Add focused CLI tests in `tests/test_sample_histogram_cumulative_fractions.py` patterned on `TestSampleHistogramFractions`, extend `tests/test_sample_option_validation.py::TestSampleOptionValidation`, and document page-local coverage in README.md and the histogram tooling rows of docs/invariants.md. Keep this one bounded option within a few hundred changed lines including tests.

**Acceptance criteria.**
- An offset 4x2 crop with ordered color counts 3, 2, 2, 1 reports cumulative fractions `0.375, 0.625, 0.875, 1.0`; tied count-2 colors retain ascending tuple order. Surrounding pixels do not affect these values. `--top-colors 2` reports `0.375, 0.625`, and adding `--color-offset 1` reports `0.25, 0.5`, with the existing original palette totals and omitted-pixel values retained. This catches accidental inclusion of skipped colors or normalization by displayed pixels.
- Excluding the count-3 color reports `0.25, 0.5, 0.625`; count/fraction filtering likewise contributes only emitted counts. An empty filtered result or a page beyond the palette emits an empty colors array. A single-color crop ends at `1.0`; a three-pixel crop with three distinct colors ends at exactly `1.0`, demonstrating integer-prefix division rather than summed rounded fractions.
- RGB mode merges opacity variants; RGBA mode keeps them separate in existing count/tuple order, including stored RGB beneath zero alpha, and opaque input uses alpha 255. Combined individual fractions, cumulative fractions and spatial diagnostics retain their independently expected values. Without the flag, no cumulative field or text suffix appears. With it alone, individual fraction fields remain absent and the existing summary-field conditions remain intact.
- Text and JSON agree on cumulative values and order; package and direct-script invocations and help expose the option. Use without histogram mode, including ordinary pixels, runs and find-color mode, exits 2 with empty stdout and `--color-cumulative-fractions requires --histogram` before image reads. Run `make check` after final edits.

### Reference-pixel sampler: page through ranked histogram colors (planned 2026-11-03 by the plan role) — done 2026-11-03 by the feature role

**Goal.** Inspect later palette entries without increasing the displayed palette or changing the crop. The existing histogram filters and `--top-colors` select a leading page; source and archive searches found coordinate pagination and worst-pixel pagination, but no histogram offset.

**Approach and files.** Add optional `--color-offset K`, default None, in `tools/sample_arguments.py::build_parser`, with a nonnegative plain ASCII integer converter in `tools/sample_validators.py` patterned on `match_pixel_offset`. In `option_error`, immediately after the existing top-colors check, require `--top-colors` for explicit offset use, including zero; the existing top-colors check continues to require histogram mode. In `tools/sample_report_histogram.py::_histogram_result`, apply exclusions and count/fraction filters before ranking by descending count then ascending RGB/RGBA tuple. Select the first `min(K + N, len(counts))` candidates with the existing heap selection and retain slice `[K:K + N]`, where N is the top-colors limit. Preserve original `total_colors` and calculate omitted pixels as region area minus emitted counts, including filtered, skipped and trailing colors. Report offset metadata only when the option is explicitly used. Spatial diagnostics continue to describe emitted colors using their complete region occurrences. Add `tests/test_sample_histogram_offset.py`, extend `tests/test_sample_option_validation.py::TestSampleOptionValidation`, and document pagination and selection storage (offset plus limit, bounded by distinct-color count) in README.md and docs/invariants.md. This is one bounded option across seven files, at most a few hundred changed lines; decoding and theme artwork stay outside its scope.

**Acceptance criteria.** Given an offset eight-pixel crop with RGB counts 3, 2, 2 and 1, `--top-colors 2 --color-offset 1` emits the two count-2 colors in ascending tuple order, with `total_colors=4` and `omitted_pixels=4`; offset 3 emits the count-1 color and omits seven pixels, and offsets 4 and 100 return an empty palette and omit eight. Excluding the count-3 color before offset 1 yields the later count-2 tuple followed by the count-1 tuple; count and fraction cutoffs likewise operate before pagination. Explicit zero matches the existing first-page report, and omitting the option preserves existing output. Fractions retain denominator eight; positions, bounds and centroids remain absolute and cover every occurrence of each emitted color. An RGBA fixture verifies opacity participates in tie order and grouping, including stored RGB under zero alpha, while RGB mode merges opacity variants and opaque input uses alpha 255. Text and JSON agree on selected colors and totals; package and direct-script invocations agree. Negative, fractional, exponent, underscore, whitespace, non-ASCII, nonnumeric and missing offsets exit 2 with empty stdout before PNG reads. Explicit offset without top-colors, including zero in histogram mode, reports `--color-offset requires --top-colors`; top-colors outside histogram retains its existing diagnostic precedence. An integer beyond Python's conversion limit fails without a traceback, while a large valid offset returns an empty page. Run `make check` after final edits.
