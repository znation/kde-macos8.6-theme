### Reference-pixel sampler: cap the displayed scanline run list (planned 2026-11-04 by the plan role)

**Goal and grounding.** Let a measurement of a large reference region show a bounded prefix of its color runs without losing full-region summaries. `tools/sample_report_runs.py::_runs_result` currently extends the report with each scanline's color/length-filtered runs; `report_runs` prints that list. Searches of the sampler, its tests, Planned entries and related archive headings found color-run length filters and run summaries, but no displayed-run limit. The finished histogram and matching-coordinate pagination features serve different report modes. This plan is independent of the waiting Plasma-selection wrapper.

**Approach and files.** Add optional `--max-runs N` in `tools/sample_arguments.py::build_parser`, using the existing positive ASCII integer validator, and require `--runs` in `option_error`. In `tools/sample_report_runs.py::_runs_result`, retain the first N eligible runs in existing traversal order across the entire region, after named-color selection/exclusion and inclusive length filters. Continue scanning to count subsequent eligible runs and to complete requested unfiltered summaries. When the limit is explicit, add top-level integer `omitted_runs` counting eligible runs beyond the displayed prefix; emit it even when zero. In `report_runs`, print `omitted runs: N` after the run list only when the limit is supplied. Bound the retained cross-scanline report list to N rather than constructing the complete region list and slicing it; the existing per-scanline `_color_runs` allocation and image decoding remain. Add `tests/test_sample_runs_limit.py` following `tests/test_sample_runs_result.py::TestSampleRunsResult`, with CLI coverage following the existing sampler tests; extend `tests/test_sample_option_validation.py`, document the option in README.md's runs section, and add a tooling row in docs/invariants.md. Scope is these six files, at most a few hundred lines including tests; pagination and other report modes are outside this change.

**Acceptance criteria.**
- For a horizontal 4x2 region whose rows are `AABB` and `ACCC` (A, B and C distinct RGB tuples), `--runs --run-axis horizontal --max-runs 2` reports the two row-zero runs, lengths 2 and 2, and `omitted_runs=2`. Limit 3 includes row one's A run at its absolute image coordinates and reports 1 omitted run; limit 4 or larger reports 0. Text and JSON expose the same prefix and omitted count. A cropped vertical rectangle similarly takes a single prefix across columns in left-to-right order, rather than restarting the limit per column.
- On that fixture, excluding A with limit 1 displays B and reports 1 omitted run (C); selecting a nonexistent color or using contradictory length cutoffs displays no runs and reports 0. Thus omitted counts describe eligible segments, not pixels or pre-filter segments. With `--run-count`, `--scanline-run-counts` and `--longest-run`, the full unfiltered results remain 4, `[2,2]` and the C run of length 3 despite truncation. An RGBA fixture verifies that opacity-separated runs consume separate slots under `--alpha`, while RGB mode merges them as before.
- Omitting the option preserves the existing JSON schema and text output. Zero, negative, fractional and non-ASCII numeric limits fail with exit 2 and empty stdout; use without `--runs` fails before image reading with a diagnostic naming both options. Help exposes the option, documentation distinguishes this prefix cap from run-length filtering and full-region summaries, and `make check` passes after the final edit.
