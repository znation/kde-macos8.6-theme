### Reference-pixel sampler: select scanline runs by RGB palette (planned 2026-11-03 by the plan role)

**Goal.** Isolate border and highlight segments of named colors in one scanline report. Histogram inclusion already exists, and color search reports matching intervals, but ordinary runs currently filter by length alone; palette selection should preserve separate equal-color segments rather than merge neighboring selected colors.

**Approach and files.** Add repeatable `--run-color RRGGBB` (destination `run_colors`, default None) to `tools/sample_arguments.py::build_parser`, using the existing `tools/sample_validators.py::rgb_argument` syntax. In `option_error`, immediately after the maximum-run-length dependency check, require `--runs`. In `tools/sample_report_runs.py::_runs_result`, form a set of requested RGB tuples once and intersect membership with the length predicates on completed `_color_runs` records. Selection ignores alpha, while segmentation continues to use RGBA when requested. Do not add output metadata. Add `tests/test_sample_runs_colors.py`, extend `tests/test_sample_option_validation.py::TestSampleOptionValidation`, and document the option in README.md and the sampler scanline invariant in docs/invariants.md. This is one option across six files, bounded to a few hundred changed lines; no new dependency or theme artwork is needed.

**Acceptance criteria.** Given a horizontal crop starting at (2,1) containing A,A,B,A,C,C, where A=(1,2,3), B=(4,5,6), C=(7,8,9), selecting A emits runs (2,1,length=2) and (5,1,length=1); selecting A and B also emits (4,1,length=1), without merging adjacent selected colors. Adding minimum length 2 retains only the first A run; maximum length 1 retains only the later A run. Duplicate selections do not duplicate records, absent colors yield an empty JSON `runs` array and text containing just the existing header/region/axis lines, and omitting selection preserves existing output fixtures. Horizontal and vertical rectangular scans retain absolute coordinates, traversal order and scanline boundaries. With RGBA input, selected RGB includes opacity variants, including stored RGB under zero alpha, but differing alpha still splits runs; without `--alpha`, equal RGB variants merge, and opaque input reports alpha 255 when requested. Text and JSON agree on retained records; package and direct-script invocation agree. Lowercase and optional `#` are accepted. Missing, short, nonhex and whitespace-padded values exit 2 with empty stdout before image access. Valid selection without runs in ordinary, histogram and search modes reports `--run-color requires --runs` before image access; tests guard both PNG readers and `os.open`. Help lists the option. Run `make check` after final edits.

### Reference-pixel sampler: select named colors in scanline runs (planned 2026-11-03 by the plan role) — done 2026-11-03 by the feature role

**Goal.** Isolate known border and stripe shades in a reference crop while retaining their separate equal-color runs. The current run report filters lengths, while named inclusion is limited to histograms; source and related finished-plan searches found no named run selection. This feature is independent of the waiting histogram plan.

**Approach and files.** Add repeatable `--run-color RRGGBB` in `tools/sample_arguments.py::build_parser`, destination `run_colors`, default None, using `tools/sample_validators.py::rgb_argument`. In `option_error`, immediately after the maximum-run-length dependency check, require `--runs` with diagnostic `--run-color requires --runs`. In `tools/sample_report_runs.py::_runs_result`, build a set of requested RGB tuples once and intersect membership with the existing length predicates on completed `_color_runs` records. Selection ignores opacity, but segmentation still uses RGB or RGBA according to `--alpha`; retain separate adjacent runs of different selected colors. Preserve the report schema, traversal order and absolute coordinates. Add `tests/test_sample_runs_colors.py` using `CliTestCase` and fixture patterns from `tests/test_sample_runs_max_length.py::TestSampleRunsMaximumLength`; extend `tests/test_sample_option_validation.py::TestSampleOptionValidation`. Document the flag beside the run length filters in README.md and amend the scanline-run row in docs/invariants.md. These six files form one bounded change of a few hundred lines including tests; decoding and search-mode diagnostics remain outside scope.

**Acceptance criteria.**
- For a crop at (2,1) containing successive pixels A,A,B,B,B,A,C,C, where A=`010203`, B=`090807`, C=`040506`, selecting A emits starts (2,1) and (7,1) with lengths 2 and 1. Selecting A and C also emits (8,1) with length 2, in scan order. Adding minimum length 2 removes the singleton A; maximum length 1 retains only that singleton. Omitted B never joins the A runs. Selecting adjacent distinct colors retains their individual run records.
- Repetition, lowercase and optional `#` give the same selection. An absent color yields JSON `runs: []` and text with image, region and axis lines but no run lines or added metadata. Selecting the complete crop palette matches the unfiltered report. Literal expected records cover an offset nonsquare rectangle in both axes, inferred single-column traversal, an explicit vertical singleton, crop-edge runs and equal colors on adjacent scanlines that remain separate. Text and JSON agree; direct-script and package invocations agree; omitting the flag retains existing fixtures.
- For adjacent RGBA pixels (1,2,3,0), (1,2,3,128), (4,5,6,255), selecting `010203` yields one length-2 run in RGB mode and two length-1 runs with their original alpha bytes in alpha mode. Minimum length 2 in alpha mode yields an empty list, proving segmentation precedes selection and length filtering. An RGB-only fixture reports alpha 255 when requested.
- Missing and malformed values exit 2 with empty stdout. Valid use outside runs mode, including ordinary samples, histogram and find-color modes, exits 2 with `--run-color requires --runs` before image access; guard `os.open`, `read_png_size` and `read_png` in validation tests. Earlier incompatible-option diagnostics retain precedence. Help lists the repeatable option and the absent parser default is None. Run `make check` after final edits.

### Reference-pixel sampler: page through ranked histogram colors (planned 2026-11-03 by the plan role) — done 2026-11-03 by the feature role

**Goal.** Inspect later palette entries without increasing the displayed palette or changing the crop. The existing histogram filters and `--top-colors` select a leading page; source and archive searches found coordinate pagination and worst-pixel pagination, but no histogram offset.

**Approach and files.** Add optional `--color-offset K`, default None, in `tools/sample_arguments.py::build_parser`, with a nonnegative plain ASCII integer converter in `tools/sample_validators.py` patterned on `match_pixel_offset`. In `option_error`, immediately after the existing top-colors check, require `--top-colors` for explicit offset use, including zero; the existing top-colors check continues to require histogram mode. In `tools/sample_report_histogram.py::_histogram_result`, apply exclusions and count/fraction filters before ranking by descending count then ascending RGB/RGBA tuple. Select the first `min(K + N, len(counts))` candidates with the existing heap selection and retain slice `[K:K + N]`, where N is the top-colors limit. Preserve original `total_colors` and calculate omitted pixels as region area minus emitted counts, including filtered, skipped and trailing colors. Report offset metadata only when the option is explicitly used. Spatial diagnostics continue to describe emitted colors using their complete region occurrences. Add `tests/test_sample_histogram_offset.py`, extend `tests/test_sample_option_validation.py::TestSampleOptionValidation`, and document pagination and selection storage (offset plus limit, bounded by distinct-color count) in README.md and docs/invariants.md. This is one bounded option across seven files, at most a few hundred changed lines; decoding and theme artwork stay outside its scope.

**Acceptance criteria.** Given an offset eight-pixel crop with RGB counts 3, 2, 2 and 1, `--top-colors 2 --color-offset 1` emits the two count-2 colors in ascending tuple order, with `total_colors=4` and `omitted_pixels=4`; offset 3 emits the count-1 color and omits seven pixels, and offsets 4 and 100 return an empty palette and omit eight. Excluding the count-3 color before offset 1 yields the later count-2 tuple followed by the count-1 tuple; count and fraction cutoffs likewise operate before pagination. Explicit zero matches the existing first-page report, and omitting the option preserves existing output. Fractions retain denominator eight; positions, bounds and centroids remain absolute and cover every occurrence of each emitted color. An RGBA fixture verifies opacity participates in tie order and grouping, including stored RGB under zero alpha, while RGB mode merges opacity variants and opaque input uses alpha 255. Text and JSON agree on selected colors and totals; package and direct-script invocations agree. Negative, fractional, exponent, underscore, whitespace, non-ASCII, nonnumeric and missing offsets exit 2 with empty stdout before PNG reads. Explicit offset without top-colors, including zero in histogram mode, reports `--color-offset requires --top-colors`; top-colors outside histogram retains its existing diagnostic precedence. An integer beyond Python's conversion limit fails without a traceback, while a large valid offset returns an empty page. Run `make check` after final edits.
