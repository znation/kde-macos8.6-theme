### Offer an explicit keyboard-swap removal command (planned 2026-11-04 by the plan role)

**Goal.** Let a user reverse the modifier swap selected by `make apply` with `make remove-keymap`, preserving their other XKB options. README currently offers only manual reversal in System Settings. Searches of the current helper, Makefile, Planned entries and finished-plan archive found no keyboard-swap removal command; the finished removal-guide entry documents the manual route.

**Approach and files.** Add `--remove` to `tools/apply_keymap.py::main` and a removal branch in `_apply`. Split and trim the comma-separated value from `_read_options`, remove exact `OPTION` tokens (including duplicates), and retain the remaining nonempty tokens in their original order. If the swap is absent, return success without writing configuration or emitting a reload. Otherwise pass the remaining comma-joined value, including an empty string when the swap was the sole option, through `_write_options`; retain `ResetOldOptions=true` so KWin clears its previously active options when applying the reduced set. Reload only after both writes succeed. Keep the current default apply path. Adjust `_reload`'s fallback notes to describe keyboard-option changes taking effect at next login, so removal does not claim that a swap will be enabled. This is explicit token removal, not restoration of a saved configuration or a claim of ownership of a pre-existing swap.

Add a public `.PHONY` `remove-keymap` target in `Makefile`, guarded by `require_python_ready` and `refuse_destdir`, invoking the helper with `--remove`; list it in `help`. Extend `tests/test_apply_keymap.py` using `StubTools` and the existing command-order/failure fixtures; add a Make dry-run assertion for the new target there. Update README's Installing and Removing the theme instructions and the keyboard-option row in `docs/invariants.md`. These five files are the scope; no automatic uninstall behavior or new dependency. Keep added behavior and tests within a few hundred lines.

**Acceptance criteria.**
- Given `caps:escape,ctrl:swap_lalt_lctl,compose:ralt,ctrl:swap_lalt_lctl`, removal writes `caps:escape,compose:ralt`, writes `ResetOldOptions=true`, then signals reload. A similarly named token such as `ctrl:swap_lalt_lctl_extra` survives. Tests independently specify the expected retained options, catching a substring-removal or wrong-branch bug.
- Given only the swap, removal writes an empty Options value and enables option reset before reload. Given an empty value or options without the swap, it exits 0 without writes or reload; a repeated removal against the resulting configuration has that same no-op outcome.
- A failed read performs no writes; a failed Options or ResetOldOptions write performs no reload and returns the existing required-command failure status. A successful removal with missing or failing reload emitters exits 0 and explains that the keyboard-option changes take effect at next login. The default apply behavior remains covered by its existing tests.
- `make -n remove-keymap` names the helper's removal flag without an install step; a nonempty DESTDIR is refused before configuration changes. `make help` and README identify the command as removing this specific swap while leaving other options, and explain that it cannot restore previous keyboard settings. The invariant row names the removal coverage, and `make check` passes after the final edit.
