### Reference-pixel sampler: page through eligible scanline runs (planned 2026-11-04 by the plan role)

**Goal and grounding.** Inspect later portions of a detailed border measurement without printing an increasing prefix. `tools/sample_report_runs.py::_runs_result` supports `--max-runs`, but retains the first eligible runs only. Searches of the sampler, tests, queue and archive found no run-offset option; the finished displayed-run cap explicitly excluded pagination. This addition is independent of the waiting Make render selector.

**Approach and files.** Add optional `--run-offset K` beside `--max-runs` in `tools/sample_arguments.py::build_parser`, parsed by a new nonnegative ASCII integer validator in `tools/sample_validators.py` following `match_pixel_offset`. In `option_error`, require `--max-runs` when the offset is supplied, including zero; the existing limit dependency continues to require `--runs`. In `_runs_result`, skip K eligible runs globally after color inclusion/exclusion and inclusive length filters, then retain at most N runs. Count skipped and trailing eligible runs together in the existing `omitted_runs`; filtered runs do not contribute. Continue computing requested summaries before filters and paging. Explicit offset adds top-level `run_offset` in JSON; `report_runs` prints `run offset: K` immediately before the displayed runs. An absent offset preserves existing output. Retain at most N cross-scanline report records, even for a large offset; per-scanline segmentation and image decoding keep their existing allocations. Add `tests/test_sample_runs_offset.py` using `CliTestCase` and generated PNGs like `TestSampleRunsLimit`, extend `tests/test_sample_option_validation.py`, document the option in README.md's runs section and extend the max-runs tooling row in docs/invariants.md. These seven files and a small counter change fit one run; other report modes are outside scope.

**Acceptance criteria.**
- For distinct RGB colors A, B, C and a horizontal 4x2 region with rows `AABB` and `ACCC`, limit 2 and offset 1 emit B at `(2,0)` with length 2, then A at `(0,1)` with length 1, and report `omitted_runs=2`, `run_offset=1`. Offset 0 emits the original first page and adds only the explicit offset metadata/line. Offset 4 or larger emits an empty list and reports 4 omitted runs. JSON and text describe the same page. A crop with a nonzero origin and vertical traversal verifies absolute coordinates and a single offset across columns.
- On that fixture, excluding A with limit 1 and offset 1 emits C and reports 1 omitted run; contradictory length cutoffs or selection of an absent color emit an empty page and report 0 omitted runs. Requested full-region summaries remain run count 4, scanline counts `[2,2]`, and longest C run length 3 despite paging. An RGBA fixture with adjacent equal RGB but differing alpha verifies that opacity-separated segments consume separate offset slots under `--alpha`, while RGB mode merges them. These expectations catch skipping before filtering or restarting the offset per scanline.
- Negative, fractional and non-ASCII offsets exit 2 with empty stdout. Offset without a limit fails before image access with a diagnostic naming `--run-offset` and `--max-runs`; offset plus limit without `--runs` also fails before image access. Omitting the offset preserves capped and uncapped report schemas and text. Help and README explain eligible-run paging, omitted-count semantics and full-region summaries; `make check` passes after the final edit.

### Fidelity diagnostics: cap the horizontal mismatch-run report (planned 2026-11-04 by the plan role)

**Goal.** Keep noisy candidate comparisons readable by limiting the horizontal mismatch intervals printed. `tools/fidelity.py::main` already filters completed intervals by length, but source, queue and archive searches found no horizontal report-count cap. This work is independent of the waiting reference-sampler pagination.

**Approach and files.** Add optional `--max-difference-runs N` (default None) in `tools/fidelity_cli_parser.py::build_parser`, using `positive_int`. In `tools/fidelity.py::main`, reject use without `--difference-runs` before source reads. After the existing minimum and maximum horizontal length filters, retain the first N eligible intervals in row-major order and compute the eligible count minus the emitted count. Pass that optional count through `tools/fidelity_reports.py::report_data` as top-level JSON `omitted_difference_runs`; `tools/fidelity_rendering.py::render_text` prints `omitted difference runs: N` immediately after the horizontal run list, including zero. Compute requested run counts and longest summaries before filtering and capping, as today. This is an output cap: retain the existing full-list segmentation, with no memory-bound claim, pagination or vertical cap. Add `tests/test_fidelity_difference_runs_limit.py` using `FidelityCliTestCase` and generated PNG fixtures like `TestDifferenceRunsMaximumLength`; document the option beside horizontal run filtering in README.md and add a tooling guarantee in docs/invariants.md. These seven files and a small post-filter slice fit one implementation run without a dependency or artwork change.

**Acceptance criteria.**
- Against a black 9x2 reference, a candidate with red-channel delta 20 at x={0,2,3,5,6,7} on row 0 and x={0,1,2,3,8} on row 1 has five horizontal intervals. Limit 2 emits exactly `(0,0,1)` and `(2,0,2)` as `{x,y,length}` records and reports 3 omitted. Minimum length 2 with limit 1 emits `(2,0,2)` and omits 2; maximum length 2 with limit 2 emits the two original leading intervals and omits 1. Contradictory length cutoffs return an empty list with 0 omitted. These outcomes catch capping before filtering and restarting the cap per row.
- Limit 5 or larger emits the complete eligible list with 0 omitted; identical images and tolerance 20 on that fixture emit an empty list with 0 omitted. Requested `difference_run_count` stays 5 and `longest_difference_run` stays `(0,1,4)` under the cap. Metrics, bounds, vertical diagnostics and verdict match the uncapped comparison, including both default failure and a passing aggregate budget. A nonzero-origin crop retains crop-relative coordinates. Text and JSON describe the same intervals and omitted count; omission of the new option adds neither metadata nor text.
- Zero, negative, fractional and non-ASCII limits, and a missing value, fail with status 2 and empty stdout. A valid limit without `--difference-runs` fails before image access with a diagnostic naming both flags. Help and README distinguish the report-count cap from the per-interval length cutoff and explain the full-list allocation. `make check` passes after the final edit.
