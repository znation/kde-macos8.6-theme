### Fidelity diagnostics: cap the horizontal mismatch-run report (planned 2026-11-04 by the plan role)

**Goal and grounding.** Bound printed horizontal mismatch intervals when examining noisy candidate renders. Searches of fidelity sources, tests, the queue and related archived horizontal-run plans found length filters but no list-size limit. This is independent of the waiting reference-sampler pagination work.

**Approach and files.** Add optional `--max-difference-runs N` (default None, existing `positive_int` validator) in `tools/fidelity_cli_parser.py::build_parser`. In `tools/fidelity.py::main`, reject use without `--difference-runs` before image reads. After the existing inclusive length filters, retain the first N eligible row-major intervals and count the eligible intervals removed. The existing full-list count and longest-run calculations must precede truncation. Pass an optional `omitted_difference_runs` keyword through `tools/fidelity_reports.py::report_data`; explicit limiting adds that top-level JSON integer even when zero. In `tools/fidelity_rendering.py::render_text`, print `omitted difference runs: N` immediately after the horizontal run list. This bounds output, not scan storage: retain the existing segmentation and full-list allocation, and document that limit plainly. Add `tests/test_fidelity_difference_runs_limit.py` using `FidelityCliTestCase` and generated PNGs, document the flag beside horizontal filters in README.md and extend the horizontal-run tooling guarantee in docs/invariants.md. These seven files form one run; vertical caps, pagination and streaming allocation are separate possible improvements.

**Acceptance criteria.**
- Given a black 9x2 reference and a candidate with red-channel delta 20 at x={0,2,3,5,6,7} on row 0 and x={0,1,2,3,8} on row 1, limit 2 emits exactly `(0,0,1)` and `(2,0,2)` as `{x,y,length}` records and reports 3 omitted intervals. Minimum length 2 plus limit 1 emits `(2,0,2)` with 2 omitted; maximum length 2 plus limit 2 emits `(0,0,1)` and `(2,0,2)` with 1 omitted. These outcomes catch truncation before filtering. Limit 5 or larger reports zero omitted; conflicting length cutoffs and identical images emit an empty list with zero omitted. JSON and text describe the same result.
- On that fixture the requested full horizontal count remains 5 and the longest summary remains `(0,1,4)` despite the cap. Comparison metrics, bounds, verdict and exit status agree with an uncapped invocation, both for default FAIL and a passing aggregate budget. An offset crop retains crop-relative interval coordinates; alpha-only mismatches participate in the capped list. Omitting the option adds neither the omitted-count key nor line and retains the existing list output.
- Zero, negative, fractional and non-ASCII limits, and a missing value, exit 2 with empty stdout. A valid limit without `--difference-runs` fails before image reads with a diagnostic naming both flags. Help documents the dependency; direct-script and package invocations agree. README explains filtering order and the output-only bound. `make check` passes after the final edit.
