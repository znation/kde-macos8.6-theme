In `tools/sample_report_search.py::report_search`, accumulate maximal contiguous horizontal matching intervals during the existing row-major scan, using its RGB-tolerance and exact-alpha predicate. These six files bound one implementation run; no theme changes or new dependencies.

Assert sum of lengths equals the full match count, with no outside-region matches included. Cover no matches, complete coverage, single-pixel, single-row and single-column regions; include tolerance boundary inclusion, exact-alpha rejection, stored RGB under alpha zero and opaque alpha fallback. ### Fidelity gate: allow an absolute differing-pixel budget (planned 2026-11-02 by the plan role)

**Goal and grounding.** Allow a fixed-size widget comparison to tolerate a specified number of mismatching pixels without calculating a fractional threshold. `tools/fidelity_metrics.py::Metrics.differing` already counts pixels beyond tolerance, but `tools/fidelity_reports.py::budget_verdict` gates only MAE, fraction, RMSE and maximum delta. Searches of source, tests and planned/finished plans found no absolute differing-count budget. This is independent of the waiting sampler plan.

**Approach and files.** Add `--max-differing N` to `tools/fidelity.py::main`, using a new `tools/fidelity_arguments.py::max_differing` argument type: accept a nonnegative plain ASCII integer through the existing `plain_number` convention, catch conversion errors, and reject negatives before image reads. No image-area upper bound is needed: a budget above the crop area simply passes this constraint. Extend `tools/fidelity_reports.py::budget_verdict` with a defaulted `max_differing=None` parameter and compare `metrics.differing <= max_differing`; supplying this budget replaces the default zero-differences gate and combines conjunctively with other supplied budgets. Extend `report_data` with a defaulted keyword-only parameter, emitting integer `thresholds.max_differing` only when supplied; `render_text` adds `max-differing=N` immediately before tolerance in its verdict line. Wire both calls from `main`, including direct-script imports, help and usage descriptions. Reuse the existing metric with no extra pixel scan. Add `tests/test_fidelity_count_budget.py` using `support.fidelity_cli_case.FidelityCliTestCase`, document the option in README.md and update the fidelity gate row in docs/invariants.md with a dated test reference. These six files bound one implementation run; no theme or decoder changes.

**Acceptance criteria.** Synthetic fixtures with independently specified mismatch counts prove inclusive boundary PASS, one-below FAIL, zero and above-area budgets, and identical-image PASS. Count each pixel once even when several RGBA channels differ. Cover tolerance equality exclusion and one-above inclusion, alpha-only changes, RGB beneath zero alpha, and opaque fallback. Different nonzero candidate/reference crop origins must exclude outside-crop differences and budget only the compared area. Exercise conjunction with each existing budget, including cases where this count passes but another budget fails and vice versa; compare text/JSON verdicts and statuses 0/1. Assert the JSON threshold is an integer and the exact text clause; without the option the new key/clause is absent and existing default regressions remain green. Reject negative, fractional, exponent, underscore, non-ASCII, whitespace and nonnumeric values, plus a missing argument, with status 2 and empty stdout before `_read_source` is called. Cover conversion-limit errors without traceback, help text and direct-script invocation. Run `make check` after final edits.
