### Reference-pixel sampler: summarize the longest scanline run (planned 2026-11-03 by the plan role)

**Goal.** Report a scanline run scan's dominant segment as a scalar instead of reading its full run list. The `--runs` mode lists every run and filters the list by color and length, but searches of the sampler, its tests and the plan archive found no longest-run summary; the finished `--longest-match-run`/`--longest-match-column-run` serve the separate `--find-color` mode and the fidelity CLI has its own longest-run pair. Independent of the waiting `--run-count` series — both touch adjacent lines in the same two tools files, and either may land first.

**Approach and files.** Add boolean `--longest-run` in `tools/sample_arguments.py::build_parser` beside the other `--runs`-only options; in `option_error`, immediately after the `--exclude-run-color requires --runs` check, require `--runs` with diagnostic `--longest-run requires --runs`. In `tools/sample_report_runs.py::_runs_result`, when the flag is requested, track the longest run of each `_color_runs` scan over the complete unfiltered line sequence — before color selection, exclusion and length filters — and record top-level `longest_run` as the first run of maximal length in scan order: top-to-bottom rows for the horizontal axis, left-to-right columns for the vertical, and the earliest start within a scanline; every scanline yields at least one run, so the summary is never null. The record mirrors the corresponding entry of `runs` — keys `x`, `y`, `length`, `rgb` as a list, `hex`, plus `alpha` under `--alpha` — without changing what `runs` contains. In `report_runs`, print `longest run: X,Y,LENGTH` on its own line immediately after the `axis:` line, before the run list. Add `tests/test_sample_longest_run.py::TestSampleLongestRun` patterned on `tests/test_sample_runs.py`'s PNG-fixture cases, extend `tests/test_sample_option_validation.py`'s rejection table, document the option in README.md's runs section and add a dated tooling row in docs/invariants.md. Six files, a few dozen changed lines including tests; histogram, search and match modes stay out of scope.

**Acceptance criteria.** A horizontal 4x3 scan whose rows form two runs of lengths 2 and 3, two runs of length 5, then one run of length 4 reports JSON `longest_run` with `length=5` at the row-1 first run and text `longest run: 0,1,5` — the first length-5 scanline wins the tie, and the earliest maximal run wins within a scanline; `--run-color` naming only the row-0 color, `--exclude-run-color` naming only the row-1 color, minimum length 4 and maximum length 3 each leave `longest_run` at the unfiltered length 5 while the listed runs follow their filters, and contradictory length cutoffs empty the list while `longest_run` stays at the length-5 run. A vertical `--run-axis` rectangle reports the longest run across columns with column-order tie resolution and absolute coordinates; a single-row scan reports that row's longest run and a 1x1 region reports it. With `--alpha`, `longest_run` mirrors the emitted record's RGBA grouping; RGB mode merges opacity variants and opaque input uses alpha 255. Omitting `--longest-run` omits the JSON key, the text line and the comparison without altering any existing field, text line or filter result. `--longest-run` without `--runs` exits 2 with `--longest-run requires --runs` and empty stdout before the PNG reads. Text and JSON agree; package and direct-script invocations agree; help exposes the flag. Run `make check` after final edits.

### Reference-pixel sampler: page through ranked histogram colors (planned 2026-11-03 by the plan role) — done 2026-11-03 by the feature role

**Goal.** Inspect later palette entries without increasing the displayed palette or changing the crop. The existing histogram filters and `--top-colors` select a leading page; source and archive searches found coordinate pagination and worst-pixel pagination, but no histogram offset.

**Approach and files.** Add optional `--color-offset K`, default None, in `tools/sample_arguments.py::build_parser`, with a nonnegative plain ASCII integer converter in `tools/sample_validators.py` patterned on `match_pixel_offset`. In `option_error`, immediately after the existing top-colors check, require `--top-colors` for explicit offset use, including zero; the existing top-colors check continues to require histogram mode. In `tools/sample_report_histogram.py::_histogram_result`, apply exclusions and count/fraction filters before ranking by descending count then ascending RGB/RGBA tuple. Select the first `min(K + N, len(counts))` candidates with the existing heap selection and retain slice `[K:K + N]`, where N is the top-colors limit. Preserve original `total_colors` and calculate omitted pixels as region area minus emitted counts, including filtered, skipped and trailing colors. Report offset metadata only when the option is explicitly used. Spatial diagnostics continue to describe emitted colors using their complete region occurrences. Add `tests/test_sample_histogram_offset.py`, extend `tests/test_sample_option_validation.py::TestSampleOptionValidation`, and document pagination and selection storage (offset plus limit, bounded by distinct-color count) in README.md and docs/invariants.md. This is one bounded option across seven files, at most a few hundred changed lines; decoding and theme artwork stay outside its scope.

**Acceptance criteria.** Given an offset eight-pixel crop with RGB counts 3, 2, 2 and 1, `--top-colors 2 --color-offset 1` emits the two count-2 colors in ascending tuple order, with `total_colors=4` and `omitted_pixels=4`; offset 3 emits the count-1 color and omits seven pixels, and offsets 4 and 100 return an empty palette and omit eight. Excluding the count-3 color before offset 1 yields the later count-2 tuple followed by the count-1 tuple; count and fraction cutoffs likewise operate before pagination. Explicit zero matches the existing first-page report, and omitting the option preserves existing output. Fractions retain denominator eight; positions, bounds and centroids remain absolute and cover every occurrence of each emitted color. An RGBA fixture verifies opacity participates in tie order and grouping, including stored RGB under zero alpha, while RGB mode merges opacity variants and opaque input uses alpha 255. Text and JSON agree on selected colors and totals; package and direct-script invocations agree. Negative, fractional, exponent, underscore, whitespace, non-ASCII, nonnumeric and missing offsets exit 2 with empty stdout before PNG reads. Explicit offset without top-colors, including zero in histogram mode, reports `--color-offset requires --top-colors`; top-colors outside histogram retains its existing diagnostic precedence. An integer beyond Python's conversion limit fails without a traceback, while a large valid offset returns an empty page. Run `make check` after final edits.
